## 总体目标
- 统一到 Node ESM 运行环境，移除/隔离浏览器与 Python 遗留代码。
- 对齐核心模块接口，消除签名不一致、返回结构冲突和重复实现。
- 精简工具库，统一网络与文件操作的实现与用法。
- 保持现有功能：配置读取、登录校验、音频/专辑解析与下载、CLI 交互。

## 现状与主要问题
- 接口不一致：
  - `index.js` 期望解析函数返回 `{success, data}`，但 `core/audioParser.js` 返回的是直接对象且要求 `headers`（`index.js`:118-126 vs `core/audioParser.js`:53-127）。
  - `downloadAlbum` 期望 `albumInfo.data.sounds`，但解析产出 `tracks`（`index.js`:196-203 vs `core/audioParser.js`:230-247）。
  - `core/login.js` 以 `response.success` 判断，但当前 `httpRequest` 不返回该字段（`core/login.js`:316-321 vs `utils/networkUtils.js`:95-101）。
- 网络工具签名混乱：
  - 解析模块以 `httpRequest({ url, ... })` 调用，工具实际签名为 `(url, options)`（`core/audioParser.js`:66 vs `utils/networkUtils.js`:53-112）。
  - `createAuthHeaders` 未包含测试期望的 `User-Agent` 且 `generateXmSign` 未导出（`utils/networkUtils.js`:125-137,145-150；测试于 `tests/networkUtils.test.js`:89-107,112-119）。
- 文件工具为浏览器实现，无法在 Node 下持久化：
  - `fileExists/readFile/writeFile/downloadFile` 等为占位实现（`utils/fileUtils.js`:21-34,441-488,364-426）。
  - `configManager` 依赖上述函数，导致配置不真实持久化（`core/configManager.js`:41-66,87-101）。
- 重复与冗余：
  - `getFileExtension/removeFileExtension/generateNumberedFilename` 在 `fileUtils` 与 `stringUtils` 重复（`utils/fileUtils.js`:299-343 vs `utils/stringUtils.js`:261-306,307-336）。
  - 文档重复：`ARCHITECTURE.md` 与 `architecture_design.md`。
  - 语言混合：`cli.py`, `main.py`, `__pycache__` 与 Node 主体不一致。

## 重构方案
- 运行时与模块组织
  - 确认项目为纯 Node ESM 应用（`package.json:type=module` 已设置），移除浏览器特定实现与 Python 产物；必要时将 Python 迁入 `legacy/python/`。
  - 目标目录结构：
    - `core/`：`config`, `api`, `auth/login`, `parser`, `downloader`, `decryptor`
    - `utils/`：`network`, `fs`, `string`
    - `interfaces/cli.js` 作为 CLI 入口
    - 根 `index.js` 保留，并仅做初始化与动态导入
- 接口统一与类型约定
  - 解析/API：统一返回“领域对象”或抛错；由调用方处理异常。建议：API 层抛错，解析层返回对象或 `null`。
  - 下载：继续返回 `{success, ...}` 结果对象（批量下载需要统计）。
  - `index.js` 改为使用 API/Parser 的一致接口；移除对不存在的 `success`/`data` 字段的依赖。
- 网络与文件工具统一
  - `httpRequest(url, options)` 作为唯一签名；所有调用统一改造。
  - `createAuthHeaders(cookie, bid)` 返回包含 `Cookie`、`xm-sign` 与默认 `User-Agent`。
  - 导出 `generateXmSign`（占位实现先保留），满足测试与后续真实实现迁移。
  - 用 Node `fs` 与 `stream` 实现 `fileExists/readFile/writeFile/getFileSize/createDirectory` 与 `downloadFile(url, filePath, { onProgress })`（支持进度回调与重试）。
- 解析与下载流程对齐
  - `audioParser` 改为围绕 `core/api.js` 的数据进行规整（字段映射为 `title/duration/type/urls` 等）；内部从 `configManager` 读出 `cookie/bid` 自动构造 `headers`。
  - `downloadSoundWithNaming` 接收解析出的 URL 与标题，不再依赖错误的 `soundInfo.data` 字段。
  - 专辑下载统一以 `tracks` 列表驱动；`index.js/downloadAlbum` 按范围切片 `tracks`。
- CLI 对齐
  - `interfaces/cli.js` 仅调用不需要显式 `headers` 的解析函数；展示信息字段与解析产出一致（`tracks` vs `sounds` 统一为 `tracks`）。
- 测试修正
  - 调整测试以匹配统一签名与 Node 环境：
    - `networkUtils.test.js` 断言 `httpRequest` 返回 `{ status, data }` 或直接 `data`（二选一，建议断言包含 `data` 字段）。
    - `createAuthHeaders` 期望包含 `User-Agent`；导出并测试 `generateXmSign`。
    - `configManager.test.js` 改为测试“返回配置对象/写入成功/更新返回新配置对象”等现实行为，而非布尔占位。
    - 文件工具测试改为 Node 语义（存在性、读写、路径处理）。
- 文档与遗留代码清理
  - 合并两份架构文档，保留 `ARCHITECTURE.md`。
  - 将 Python 文件移入 `legacy/python/` 或删除；清空 `__pycache__/`。
