## 一、复盘背景

本项目是一个零生产依赖的 Node.js CLI 工具，用于下载喜马拉雅音频。2026 年 5 月
的四轮代码审查（存档见上文）记录了 **6 个严重问题、8 个重要问题、6 个一般问题**
与 10 条改进建议，但**长期无人修复**。本次重构的目标是：

1. 对项目做一次完整复盘，把审查报告中的问题清单真正清零
2. 对界面与工程结构进行现代化重新设计
3. 补齐历史上"只提 issue 不落地"的未完成需求

## 三、本次落地的改进

### 3.1 结构现代化（src/ 分层布局）

```
重构前                          重构后
core/                     →     src/core/     （新增 api.js 统一 API 层）
utils/                    →     src/utils/
interfaces/cli.js (806行) →     src/cli/app.js + commands/ + ui/
index.js                  →     bin/xmly.js + src/index.js（index.js 保留兼容垫片）
```

- 新增 `src/core/api.js`：所有喜马拉雅接口调用收敛到一处，统一请求头、
  业务码校验（`ret === 200`）、错误记录（`getLastApiError`）与输入解析
  （`extractIdFromInput` 支持 URL 直贴）。文档与代码不一致问题就此消除。
- 原 806 行的 `cli.js` 拆分为 `app.js`（主循环）+ `commands/`（下载/账号/
  设置）+ `ui/`（可复用终端组件），单文件职责清晰。
- 通过 `git mv` 迁移，保留文件历史。

### 3.2 界面现代化（零依赖终端 UI）

`src/cli/ui/` 提供 5 个组件，全部基于原生 ANSI 转义序列，**未引入任何
运行时依赖**，延续项目零依赖哲学：

| 组件 | 能力 | 降级策略 |
|------|------|----------|
| `ansi.js` | 颜色、光标控制 | 非 TTY / `NO_COLOR` 时自动变为纯文本 |
| `select.js` | ↑/↓ 方向键菜单、y/n 确认、文本输入 | 非 TTY 降级为数字问答 |
| `spinner.js` | Braille 加载动画（成功/失败状态） | 非 TTY 输出静态文本 |
| `progress.js` | 进度条 + 大小 + 速率 | 非 TTY 每 20% 打印一次 |
| `banner.js` | 欢迎横幅 + 登录状态 | — |

交互流程升级：粘贴 URL 即可下载、音质菜单只列出实际可用项、专辑下载
支持范围选择与序号前缀开关、下载完成后展示保存路径与统计。

### 3.4 修复过程中发现的深层缺陷（本次新修复）

1. **下载残留文件误判**：下载失败后残留的半截文件会被"跳过已存在"逻辑
   当作成功续传，导致永久性坏文件。现在失败时自动清理残留。
2. **HTTP 状态码被忽略**：旧实现不检查状态码，404 页面会被当 JSON 解析。
   现在区分 5xx/429（重试）与 4xx（立即失败），并在错误对象上携带状态码。
3. **100 集以上专辑文件排序错乱**：序号固定两位补零，`100` 按字典序排在
   `11` 前。现在宽度自适应（`max(2, digits)`）。
4. **仓库卫生**：`node_modules` 从 git 索引移除（Windows 迁移产物导致
   macOS 权限错误）、删除杂散 `file.txt`、补 `.gitignore`（`.venv/` 等）。

### 3.5 有意做出的取舍

- **TypeScript（roadmap #5）**：暂不迁移。理由：项目以零依赖、零构建
  快速上手为核心卖点；现有 JSDoc 注释覆盖完整，配合 ESLint 已能覆盖大
  部分类型安全需求。若未来代码规模显著增长，建议以
  `tsc --checkJs`（纯检查、无构建产物）作为过渡方案，而非全面改写。
- **批量解密接口（N2）**：`batchDecryptUrlsAsync` 是同步操作的伪并发，
  但属于公开 API，为兼容保留并在文档标注。
- **解密算法**：VIP URL 解密依赖平台私有映射表，无法构造真实密文测试
  向量（映射表有损），测试以错误契约为主。这是平台对抗的本质限制，
  无法在仓库内根治。

## 五、遗留事项与建议

1. **真实环境回归**：解密算法与接口形状只能用真实账号验证，建议在
   有会员权限的账号上完成一次人工回归（免费 + VIP 音频各一次）。
2. **TypeScript 检查**：若引入 `tsc --checkJs`，预计需先补齐核心模块的
   JSDoc 类型标注（当前约 80% 覆盖）。
3. **请求缓存（roadmap #10）**：如未来加入"缓存专辑页"需求，建议在
   `api.js` 内实现带 TTL 的 LRU，而非在调用方处理。
4. **发布**：建议打 `v3.0.0` 标签并发布 GitHub Release，Release Notes
   引用本报告与 CHANGELOG。

## 六、结论

本次重构把项目从"功能可用但债台高筑"推进到"结构清晰、测试可信、
体验现代"的状态：所有历史审查中的严重与重要问题全部闭环，测试从
47.5% 失败率变为 135/135 全绿，界面在保持零生产依赖的前提下完成
现代化。项目当前的工程质量可以支撑后续的功能迭代。
